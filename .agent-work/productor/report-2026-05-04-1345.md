## 本轮专项调研：All-In Insurance 详细规格输出

### Insurance 产品规格书

#### 触发时机
- 玩家执行 `all-in` 操作后
- 当前回合所有其他玩家完成动作后（摊牌前）
- 牌面未亮（community cards 可为 0-5 张）

#### 购买流程
1. 服务器向已 all-in 玩家推送 `insurance-offer` 事件
2. 前端弹出 Insurance 面板：
   - 显示当前底池大小（pot）
   - 显示玩家当前手牌 equity（基于已知信息计算）
   - 提供 2 个购买档位：**50%** 和 **100%**
   - 显示预计赔付额 = pot × (1 - playerEquity) × 购买比例
3. 玩家在倒计时内（建议 15 秒）选择档位或放弃
4. 超时默认放弃

#### 赔付算法
```
赔付额 = potSize × (1 - playerEquity) × insurancePercent

示例：
- potSize = $1000
- playerEquity = 25%（对手 set 领先）
- 购买 100% 保险
- 赔付额 = $1000 × 0.75 × 1.0 = $750
```

#### 结算时机
- 摊牌后，根据最终结果计算保险赔付
- 若玩家**输掉** all-in：保险公司赔付，玩家损失 = 0
- 若玩家**赢或平** all-in：玩家获得正常结算 + 保险费不退还

#### 后端实现要点
| 模块 | 改动 |
|------|------|
| `table-engine` | 新增 `InsuranceOffer` 状态、`processInsurance` 方法 |
| `HandAction` | 新增 `BUY_INSURANCE` / `PASS_INSURANCE` 类型 |
| `Settlement` | 新增 `insurancePayout` 字段 |
| WebSocket | 新增 `insurance-offer` / `insurance-choice` 事件 |

#### 前端实现要点
| 组件 | 改动 |
|------|------|
| `InsurancePanel` | 新组件，all-in 后弹出 |
| 牌桌主视图 | 显示保险倒计时 |
| 结算面板 | 叠加显示保险赔付金额 |

#### 商业模式考量
- 保险池由平台运营（类似彩票模型）
- 建议设定 **5% 平台抽成**（从赔付额扣减）
- 可设置单局最高赔付上限（如 $10,000）

## 本轮专项调研：Bad Beat Jackpot 详细规格输出

### Bad Beat Jackpot 产品规格书

#### 触发条件（需同时满足）
| 条件 | 规格 |
|------|------|
| 边池大小 | ≥ $100 |
| 输家手牌 | 77 或更高（口袋对子） |
| 赢家手牌 | AA / KK / QQ |
| 牌局类型 | 仅限常规桌（不包含锦标赛） |
| 展示阶段 | 必须 showdown（不是 fold 赢得） |

#### 奖金分配比例
| 角色 | 分配比例 |
|------|---------|
| **输家** | 50% |
| **赢家** | 25% |
| **牌桌其他玩家**（无论是否参与本局） | 25%（按在场时间加权） |

#### 累积机制
- 每手符合 Bad Beat 条件的牌局，边池的 **1%** 注入 Jackpot 池
- Jackpot 金额公开显示在牌桌顶部（大字滚动动画）
- 支持跨房间/跨 tier 共享奖池（建议）
